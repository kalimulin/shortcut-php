# shortcut-php — единый PHP-бэкенд сервиса «Короткие ссылки»

Автономный PHP 8.1+ монолит для обычного PHP-хостинга (Apache / Nginx + PHP-FPM + MySQL/MariaDB), объединяющий функциональность:

- `shortcut-core` (ссылки, кампании, теги, `claim` гостевых ссылок, статистика, экспорт CSV/XLSX);
- `url-security` (комплексная проверка безопасности URL: Google Safe Browsing, VirusTotal v3, URLhaus, реестр запрещённых ресурсов РФ, чёрный и белый списки, кэш с TTL);
- публичные гостевые ручки (`/api/public/*`, генерация QR-кодов в SVG);
- редирект `/s/{code}` с синхронной записью кликов в MySQL;
- собственную JWT-авторизацию и профиль пользователя (`/api/auth/*`, `/api/profile`).

Не требует Docker, фоновых воркеров, сложных очередей задач, Composer на сервере и расширений GD/Imagick.

## Требования хостинга

- PHP **8.1+** с расширениями `pdo_mysql`, `json`, `mbstring`, `zip` (для XLSX)
- MySQL **5.7+** или MariaDB **10.2+** (InnoDB, `utf8mb4`)
- Apache с `mod_rewrite` (`.htaccess` в комплекте) либо Nginx + PHP-FPM (`config/nginx.example.conf`)

## Развёртывание на PHP-хостинге (один домен)

1. Создайте базу данных MySQL в панели хостинга и импортируйте:
   - `database/migrations/001_init.sql`
   - `database/seeds/001_seed.sql` *(опционально: создаёт админа `admin@example.com` / `password` — сразу смените пароль!)*
2. Загрузите файлы:
   - Папку `backend/` (`src/`, `database/`, `.env`) разместите **выше** `public_html/` (либо внутри `public_html/backend/` с `backend/.htaccess`: `Require all denied`).
   - В `public_html/` положите сборку `cherry-frontend/dist/*`, а также `public/.htaccess`, `public/api.php` и `public/redirect.php`.
3. Скопируйте `.env.example` в `.env` рядом с `src/` и заполните:
   - `APP_URL`, `SHORTCUT_BASE_HOST` — ваш домен;
   - `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`;
   - `JWT_SECRET` — случайная строка длиной от 32 символов.
4. Проверьте работу: `GET https://ваш-домен/api/info` → `{"version":"1.0.0","status":"ok"}`.

## Локальный запуск (PHP built-in server)

```bash
cp .env.example .env
# настройте DB_* и CORS_ALLOWED_ORIGIN=http://localhost:5173
php -S 127.0.0.1:8000 router_dev.php
```

## Периодическая очистка базы данных (Cron на хостинге)

В системе реализована автоматическая очистка устаревших данных по правилам:
1. **Анонимные (гостевые) ссылки** удаляются через **48 часов** после создания (настраивается параметром `PUBLIC_SHORTCUT_TTL_HOURS=48`). При удалении ссылки также очищаются все её переходы (`click_events`) и теги (`shortcut_tags`).
2. **Неподтверждённые пользователи** удаляются через **48 часов** после регистрации (настраивается параметром `UNVERIFIED_USER_TTL_HOURS=48`). В письмо подтверждения регистрации добавлено явное предупреждение о том, что аккаунт будет удален, если его не подтвердить в течение 48 часов. При удалении аккаунта удаляются также связанные кампании, токены и ссылки.
3. **Истёкшие служебные данные** (токены верификации email, токены сброса пароля и старые счётчики rate limits) очищаются попутно при каждом запуске.

### Вариант 1: Запуск через CLI (рекомендуется для cPanel / Beget / TimeWeb / SSH)

Настройте запуск скрипта в планировщике хостинга (Cron) раз в час:

```bash
# Каждые 60 минут:
0 * * * * /usr/bin/php /home/username/backend/bin/cleanup.php --quiet >/dev/null 2>&1
```

Параметры скрипта:
- `php bin/cleanup.php` — стандартный запуск с выводом отчёта в консоль;
- `php bin/cleanup.php --dry-run` — тестовый прогон (подсчёт кандидатов на удаление без изменения БД);
- `php bin/cleanup.php --quiet` — тихий режим без вывода (для cron, чтобы не спамить почту владельца);
- `php bin/cleanup.php --json` — вывод отчёта в формате JSON.

### Вариант 2: Запуск через веб-запрос (Web Cron / URL Cron)

Если панель хостинга поддерживает запуск задач только по URL (или вы используете внешние cron-сервисы):

1. В `.env` задайте надёжный ключ:
   ```env
   CRON_SECRET_KEY=ваш_случайный_секретный_ключ_не_менее_32_символов
   ```
2. Настройте периодический вызов URL раз в час:
   ```bash
   # Через curl:
   curl -s -X POST "https://ваш-домен/api/cron/cleanup?key=ваш_случайный_секретный_ключ_не_менее_32_символов" >/dev/null 2>&1

   # Либо через wget:
   wget -q -O - "https://ваш-домен/api/cron/cleanup?key=ваш_случайный_секретный_ключ_не_менее_32_символов" >/dev/null 2>&1
   ```
   Также ключ можно передавать в заголовке `X-Cron-Key: ваш_случайный_секретный_ключ`.
   Для тестовой проверки доступен параметр `?dryRun=1`.

## Синхронизация безопасности ссылок (Cron)

В систему встроен скрипт `bin/security_sync.php`, который:
1. Загружает и обновляет локальную базу запрещённых ресурсов РФ (зеркала Единого реестра РКН);
2. Очищает устаревшие записи кэша проверок (`url_check_cache`);
3. Проводит периодический аудит существующих активных ссылок в базе данных: при обнаружении вредоносного контента ссылка автоматически переводится в статус `blocked` с фиксацией причины.

### Вариант 1: Запуск через CLI (Cron хостинга)

```bash
# Раз в сутки в 03:00 (рекомендуется):
0 3 * * * /usr/bin/php /home/username/backend/bin/security_sync.php --quiet >/dev/null 2>&1
```

Параметры запуска:
- `php bin/security_sync.php` — выполнение полной синхронизации и аудита;
- `php bin/security_sync.php --sync-rf` — только обновление реестра РФ;
- `php bin/security_sync.php --prune-cache` — только очистка устаревшего кэша проверок;
- `php bin/security_sync.php --scan-links` — только фоновое сканирование активных ссылок;
- `php bin/security_sync.php --quiet` — тихий режим без вывода;
- `php bin/security_sync.php --json` — вывод отчёта в формате JSON.

### Вариант 2: Запуск через веб-запрос (Web Cron / URL Cron с CRON_SECRET_KEY)

Если запуск настроен через внешние веб-сервисы cron или панель хостинга по URL:

```bash
# Через curl (POST или GET):
curl -s -X POST "https://ваш-домен/api/cron/security-sync?key=ваш_секретный_ключ_CRON_SECRET_KEY" >/dev/null 2>&1

# Либо через wget:
wget -q -O - "https://ваш-домен/api/cron/security-sync?key=ваш_секретный_ключ_CRON_SECRET_KEY" >/dev/null 2>&1
```

Также ключ можно передавать в заголовке `X-Cron-Key: ваш_секретный_ключ`.  
Дополнительные параметры запроса:
- `?syncRf=1` — запустить только обновление реестра РФ;
- `?pruneCache=1` — запустить только очистку кэша проверок;
- `?scanLinks=1&scanLimit=100` — запустить только сканирование ссылок (по умолчанию лимит 100);
- По умолчанию без параметров выполняются все три этапа синхронизации.
